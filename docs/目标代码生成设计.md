# Pascal-S 到 C 目标代码生成设计

## 1. 目标

目标代码生成阶段负责把“已通过语义分析的 Pascal-S AST”翻译成等价的 C 程序。

这一阶段的前提是：

- AST 已构造完成
- AST 结构已通过 `ast_validate`
- 语义分析已通过，或者至少已经产出完整的语义结果

代码生成阶段不再负责：

- 标识符是否声明
- 类型是否合法
- 参数是否匹配
- 数组是否被正确下标

这些问题都应在语义分析阶段解决。

## 2. 设计原则

代码生成应遵循以下原则：

- 语义等价优先
- 结构清晰优先
- 便于调试和验证
- 不追求复杂优化

当前课程设计场景下，最合适的目标是“生成可读、可编译的 C99 代码”。

## 3. 输入与输出

### 3.1 输入

- AST 根节点
- 语义分析结果 `SemanticResult`

代码生成必须依赖语义分析阶段提供的信息，而不是自己重新推导。

### 3.2 输出

- 一段完整的 C 源代码字符串
- 或直接写入 `.c` 文件

推荐接口：

```cpp
class CodeGenerator {
public:
    std::string generate(const AstNode *root, const SemanticResult &sem);
};
```

## 4. 模块划分

建议新增：

- `codegen.hpp`
- `codegen.cpp`

推荐主类：

```cpp
class CodeGenerator {
public:
    std::string generate(const AstNode *root, const SemanticResult &sem);

private:
    void emit_program(const AstNode *node);
    void emit_global_block(const AstNode *block);
    void emit_subprogram(const AstNode *node);
    void emit_stmt(const AstNode *node);
    std::string emit_expr(const AstNode *node);
};
```

同时建议维护：

- 输出缓冲区 `std::ostringstream out`
- 当前缩进级别 `indent_level`
- 对语义结果的只读引用

## 5. 输出文件整体结构

建议生成的 C 文件结构如下：

```c
#include <stdio.h>
#include <stdbool.h>

/* 可选：布尔输入输出辅助函数 */

/* 全局常量和变量 */

/* 函数 / 过程原型 */

/* 函数 / 过程定义 */

int main(void) {
    /* 主程序语句 */
    return 0;
}
```

其中主程序体应翻译为 `main`，而主程序块中的全局声明应放在文件作用域，而不是全部塞进 `main` 内部。

原因是 Pascal-S 的过程和函数可能访问主程序层定义的变量。

## 6. 对语义分析结果的依赖

代码生成阶段至少依赖以下语义信息：

- 每个符号的 `c_name`
- 每个表达式的类型
- 每个引用节点对应哪个符号
- 哪些左值节点表示“函数返回值赋值”

如果缺少这些信息，代码生成就不得不重新做一次语义推导，容易出现不一致。

## 7. C 侧命名策略

Pascal 标识符不能直接无条件照搬到 C。

建议在语义分析阶段为每个符号分配唯一 C 名称：

- 全局变量：`g_<name>`
- 局部变量：`l_<name>`
- 参数：`p_<name>`
- 过程 / 函数：`fn_<name>`
- 常量：`c_<name>`

目的：

- 避免与 C 关键字冲突
- 避免不同作用域同名变量冲突
- 简化代码生成逻辑

因此代码生成阶段不应自己再决定名字，而是直接使用 `symbol.c_name`。

## 8. 类型映射规则

### 8.1 基本类型

- `integer` -> `int`
- `real` -> `double`
- `boolean` -> `bool`
- `char` -> `char`
- `procedure` 返回类型 -> `void`

### 8.2 数组类型

Pascal-S：

```pascal
array[1..10] of integer
```

建议生成：

```c
int name[10];
```

若为多维数组：

```pascal
array[1..10, 0..5] of integer
```

建议生成：

```c
int name[10][6];
```

数组维度长度公式为：

```text
length = high - low + 1
```

注意：

- C 数组只记录长度，不保留 Pascal 下界
- Pascal 原始下界信息仍需从语义类型中读取，用于生成下标平移表达式

## 9. 常量和变量声明生成

### 9.1 常量声明

常量可以生成成文件作用域或局部作用域的 `const` 变量：

```c
const int c_limit = 10;
const double c_pi = 3.14;
```

字符常量按 `char` 处理。

### 9.2 变量声明

标量变量示例：

```c
int g_i;
double l_x;
bool p_flag;
```

数组变量示例：

```c
int g_arr[10];
double l_mat[10][6];
```

## 10. 子程序生成策略

### 10.1 过程映射

Pascal-S `procedure` 生成成 C `void` 函数。

例如：

```pascal
procedure p(x: integer; var y: integer);
```

建议生成：

```c
void fn_p(int p_x, int *p_y)
```

### 10.2 函数映射

Pascal-S `function` 生成成 C 普通函数。

例如：

```pascal
function f(x: integer): real;
```

建议生成：

```c
double fn_f(int p_x)
```

### 10.3 `var` 参数映射

Pascal 的 `var` 参数本质上是引用传递，建议统一映射为 C 指针参数。

规则：

- 值参数 -> 普通参数
- `var` 参数 -> 指针参数

例如：

```pascal
procedure swap(var a, b: integer);
```

生成：

```c
void fn_swap(int *p_a, int *p_b)
```

## 11. 函数返回值处理

Pascal-S 函数体内通过“给函数名赋值”来设置返回值，C 不支持这一写法。

建议统一采用“隐藏返回变量”方案：

```c
int fn_sum(int p_a, int p_b) {
    int __result = 0;
    __result = p_a + p_b;
    return __result;
}
```

实现规则：

1. 进入函数体时声明 `__result`
2. 语义分析阶段标记为“函数结果赋值”的左值，生成时输出为 `__result`
3. 函数末尾统一 `return __result;`

默认初值可按类型给出：

- `int` -> `0`
- `double` -> `0.0`
- `bool` -> `false`
- `char` -> `'\0'`

## 12. 表达式生成规则

表达式生成建议封装为：

```cpp
std::string emit_expr(const AstNode *node);
```

并保证每个复杂子表达式都带括号，降低优先级错误风险。

### 12.1 字面量

- `AST_INT_LITERAL` -> 直接输出整数
- `AST_REAL_LITERAL` -> 输出十进制浮点值
- `AST_CHAR_LITERAL` -> 输出合法 C 字符字面量

字符常量由于词法阶段保存的是原始文本，代码生成时应统一做一次 C 转义兼容处理。

### 12.2 变量引用

普通变量：

```c
g_x
```

值参数：

```c
p_x
```

`var` 参数作为表达式使用时：

```c
(*p_x)
```

### 12.3 数组访问

Pascal 数组下标与 C 不同，必须做下标平移。

例如：

```pascal
a[i]
```

若 `a` 定义为 `array[1..10] of integer`，应生成：

```c
g_a[(i) - 1]
```

若多维数组：

```pascal
m[i, j]
```

对应：

```c
g_m[(i) - low1][(j) - low2]
```

规则：

- 每一维下标表达式都要减去对应下界
- 下界来自语义类型中的 `bounds`

### 12.4 函数调用

普通函数调用直接生成：

```c
fn_f(arg1, arg2)
```

若某形参是 `var` 参数，对应实参应传地址：

```c
fn_swap(&(g_x), &(g_y))
```

对于数组元素、普通变量、`(*p_x)` 这类左值，都应能正确取地址。

### 12.5 一元运算

- `-x` -> `(-(<expr>))`
- `not x` -> `(!(<expr>))`

### 12.6 二元运算

运算符映射建议如下：

- `=` -> `==`
- `<>` -> `!=`
- `<` -> `<`
- `<=` -> `<=`
- `>` -> `>`
- `>=` -> `>=`
- `+` -> `+`
- `-` -> `-`
- `*` -> `*`
- `/` -> `/`
- `div` -> `/`
- `mod` -> `%`
- `and` -> `&&`
- `or` -> `||`

注意两点：

1. Pascal `/` 是实数除法
2. `div` 才是整数除法

因此对于 Pascal `/`，若两边都是整数表达式，也建议显式提升：

```c
((double)(lhs) / (double)(rhs))
```

## 13. 语句生成规则

### 13.1 赋值语句

普通赋值：

```c
lhs = rhs;
```

若左值被语义分析标记为函数返回值引用，则生成：

```c
__result = rhs;
```

### 13.2 过程调用语句

过程调用与函数调用的差别只在返回值是否被使用。

示例：

```c
fn_print(g_x);
```

若包含 `var` 参数，按地址传递。

### 13.3 复合语句

Pascal `begin ... end` 映射为 C 代码块：

```c
{
    ...
}
```

### 13.4 条件语句

```pascal
if cond then s1 else s2
```

生成：

```c
if (cond) {
    ...
} else {
    ...
}
```

若没有 `else` 分支，只输出 `if` 块。

### 13.5 `for` 语句

Pascal-S 当前仅支持：

```pascal
for i := start to finish do stmt
```

建议不要直接生成：

```c
for (i = start; i <= finish; ++i)
```

因为 Pascal 的终值表达式应只求值一次。

推荐生成：

```c
{
    int __for_end_1 = finish;
    for (i = start; i <= __for_end_1; ++i) {
        ...
    }
}
```

这样可以避免 `finish` 含副作用或依赖循环体修改时与 Pascal 语义不一致。

### 13.6 `read` 语句

为了实现稳定，建议每个参数单独生成一条输入语句，而不是把所有参数拼到同一个 `scanf`。

示例：

```pascal
read(i, x, ch)
```

可生成：

```c
scanf("%d", &g_i);
scanf("%lf", &g_x);
scanf(" %c", &g_ch);
```

布尔输入建议单独用辅助函数包装，避免直接把 `true/false` 文本解析交给 `scanf`。

### 13.7 `write` 语句

同样建议逐项输出，而不是一次拼复杂格式串。

例如：

```pascal
write(i, x, ch)
```

可生成：

```c
printf("%d", g_i);
printf("%g", g_x);
printf("%c", g_ch);
```

布尔输出建议单独走辅助函数：

```c
static void write_bool(bool value) {
    printf("%s", value ? "true" : "false");
}
```

## 14. 输入输出格式映射

建议映射如下：

- `integer`
  - `read` -> `"%d"`
  - `write` -> `"%d"`
- `real`
  - `read` -> `"%lf"`
  - `write` -> `"%g"`
- `char`
  - `read` -> `" %c"`
  - `write` -> `"%c"`
- `boolean`
  - `read` -> 单独辅助函数
  - `write` -> 单独辅助函数

这样实现简单，而且对逐项读写逻辑最稳妥。

## 15. 原型和定义生成顺序

为了避免函数先用后定义的问题，建议先输出所有子程序原型，再输出定义。

推荐顺序：

1. 头文件
2. 辅助函数
3. 全局声明
4. 子程序原型
5. 子程序定义
6. `main`

## 16. 缩进和输出组织

建议维护统一缩进函数：

```cpp
void emit_indent();
void emit_line(const std::string &text);
```

风格建议：

- 使用 4 空格缩进
- 每条语句单独一行
- 代码块花括号单独占位
- 表达式内部尽量加括号

课程设计场景下，可读性比最短输出更重要。

## 17. 错误处理策略

代码生成阶段原则上只在语义通过后执行。

因此推荐策略是：

- 若 `SemanticResult.ok == false`，则不进入代码生成
- 代码生成内部可以用 `assert` 或显式检查保证语义前提成立

不建议在代码生成阶段继续默默吞掉不可能状态，否则会掩盖前面语义阶段的漏洞。

## 18. 与驱动程序集成方式

建议把当前驱动流程扩展为：

```cpp
AstNode *root = parse_pascal_file(path);
if (root == nullptr) { ... }

if (!ast_validate(stderr, root)) { ... }

SemanticAnalyzer analyzer;
SemanticResult sem = analyzer.analyze(root);
if (!sem.ok) {
    print_semantic_errors(sem.errors);
    return 1;
}

CodeGenerator gen;
std::string c_code = gen.generate(root, sem);
```

生成结果可以：

- 直接输出到标准输出
- 或写入指定 `.c` 文件

## 19. 当前文法下的边界与约束

代码生成设计需要严格服从当前前端能力：

- 当前没有布尔字面量 `true` / `false`
- 当前只有 `for ... to ... do`
- 当前数组元素类型只支持基本类型
- 当前没有字符串字面量
- 当前没有记录、指针、集合等复杂结构

因此代码生成不应超前设计成“完整 Pascal 到 C 编译器”，而应围绕现有 AST 节点精确落地。

## 20. 实现顺序建议

建议按以下顺序实现代码生成模块：

1. 先完成类型映射和声明生成
2. 完成标量表达式生成
3. 完成数组访问和平移下标
4. 完成赋值、调用、`if`、复合语句
5. 完成函数返回值隐藏变量机制
6. 完成 `for`
7. 完成 `read` / `write`
8. 最后整理输出格式和辅助函数

这样可以先打通“声明 + 表达式 + 语句 + main”的主链路，再逐步补齐 Pascal-S 的特有语义映射。
