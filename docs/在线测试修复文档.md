# 在线测试修复文档

本文档整理在线评测和封闭集定位过程中发现并修复的问题。

## 1. 函数返回值变量在 `read` 中识别错误

问题所在的测试文件：封闭集样例，包含 `read(函数名)` 的函数返回值输入用例。

问题描述：函数名作为 `read` 参数时，原实现没有把它识别为当前函数返回值变量，而是按普通函数表达式处理，导致语义分析误报不可赋值。

负责模块：语义分析。

解决方案：统一赋值目标判定规则，使赋值语句左侧和 `read` 参数都能识别当前函数返回值变量；同时保留作用域遮蔽和可赋值性检查。

最终是否解决：是

## 2. 在线样例使用的语言形式超出原子集

问题所在的测试文件：封闭集样例，包含 `'Not exist'`、`'--'` 等多字符单引号常量的用例；封闭集图着色样例，包含 `Break;` 的用例。

问题描述：在线封闭集使用了原实现未覆盖的语言形式，包括多字符单引号字符串常量和 `break` 循环控制语句。原实现只支持单字符常量，也没有 `break` 语句结构，因此会在词法、语法或后续阶段失败。

负责模块：词法分析、语法分析与 AST 构造，联动语义分析和目标代码生成。

解决方案：将字符串常量和 `break` 语句纳入当前 Pascal-S 子集。字符串常量允许作为常量值和输出项；`break` 作为循环控制语句进入 AST，并在语义阶段限制其只能出现在循环内部。

最终是否解决：是

## 3. 递归调用中的实参临时状态污染

问题所在的测试文件：在线评测 93 号样例，递归 Simpson 积分相关测试。

问题描述：该样例在本地输出正确，但在在线环境下输出错误。问题集中出现在递归积分链路中，表现为数值结果明显偏差。

负责模块：目标代码生成。

解决方案：将函数调用实参临时存储设计为随函数调用栈独立存在，避免递归调用共享同一批临时状态；同时继续固定实参求值顺序，避免依赖 C 语言未指定的求值行为。

最终是否解决：是
