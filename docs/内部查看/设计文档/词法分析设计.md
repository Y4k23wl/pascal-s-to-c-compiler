# Pascal-S 词法分析设计

## 1. 目标

词法分析是编译流水线的第一阶段，位于源文件读取之后、语法分析之前。它的职责是把 Pascal-S 源程序的字符流切分为带有语义值和位置信息的 Token 流，并向后续阶段交付以下能力：

- 识别 Pascal-S 的全部保留字、运算符、界符
- 识别标识符、整型常量、实型常量、字符常量、字符串常量
- 跳过空白与两类注释（`{ ... }` 块注释、`//` 行注释）
- 维护精确到行列的源位置（`yylloc`）
- 对非法字符、未闭合注释、未闭合字符常量、以数字开头的标识符进行有界限的错误报告
- 在错误过多或语法分析提前要求停止时安全地结束扫描，不再向 Bison 输送无意义的 Token

工程上，词法器由 Flex 生成（`frontend/pascal_s_lexer.l` → `pascal_s_lexer.c`），并通过 Bison 生成的 `yylex` 接口被 `parse_pascal_stream` 间接调用。

## 2. 输入与输出

### 2.1 输入

- 任意 `FILE *`（通常由 `parse_pascal_file` 打开，或 `parse_pascal_stream` 接受外部流）
- Flex 内部的 `yyin` / `yyrestart` 负责实际的字符级缓冲

### 2.2 输出

每次成功匹配一个词法规则后，词法器向 Bison 返回：

- Token 编号（`enum yytokentype`，见 `pascal_s_parser.tab.h`）
- Token 语义值 `yylval`（联合体 `YYSTYPE`：`sval` / `ival` / `fval`）
- Token 位置 `yylloc`（`YYLTYPE`：`first_line/column`、`last_line/column`）

错误信息直接通过 `stderr` 输出，统一格式为：

```
[词法错误] 行：<line>，列：<col> - <描述>[：<上下文>]
```

错误状态额外通过以下导出函数暴露给前端：

- `int lexer_had_error(void)`
- `int lexer_error_count(void)`
- `int lexer_scan_terminated_early(void)`

## 3. 模块划分

词法分析模块只包含一份源码与对应的生成产物：

| 文件 | 角色 |
| --- | --- |
| `frontend/pascal_s_lexer.l` | Flex 源文件，规则定义、动作、辅助 C 代码 |
| `frontend/pascal_s_lexer.c` | Flex 生成的扫描器实现（CMake 构建时再生成） |
| `frontend/pascal_s_parser.tab.h` | Bison 生成的 Token 编号与 `YYSTYPE` / `YYLTYPE` 定义，被 `.l` 通过 `#include` 引入 |

对外暴露的接口（在 `.l` 文件尾部实现，由 `.y` 前部声明）：

```c
void lexer_reset_position(void);
int  lexer_had_error(void);
int  lexer_error_count(void);
int  lexer_scan_terminated_early(void);
```

由语法分析侧反向提供的协作接口：

```c
int pascal_s_should_stop_scanning(void);
```

该函数在 `pascal_s_parser.y` 中实现，用来让语法器在错误过多时通知词法器立即终止扫描。

## 4. Token 表

Token 编号由 Bison 统一分配（见 `pascal_s_parser.tab.h:41-97`），词法侧只负责返回。下表按语义分类汇总。

### 4.1 保留字（大小写不敏感）

`%option caseless` 已开启，所有保留字大小写不敏感。

| 词素 | Token | 词素 | Token |
| --- | --- | --- | --- |
| `program` | `PROGRAM` | `const` | `CONST` |
| `var` | `VAR` | `procedure` | `PROCEDURE` |
| `function` | `FUNCTION` | `begin` | `BEGIN_KW` |
| `end` | `END_KW` | `if` | `IF` |
| `then` | `THEN` | `else` | `ELSE` |
| `for` | `FOR` | `to` | `TO` |
| `do` | `DO` | `while` | `WHILE` |
| `break` | `BREAK` | `read` | `READ` |
| `write` | `WRITE` | `array` | `ARRAY` |
| `of` | `OF` | `integer` | `INTEGER` |
| `real` | `REAL` | `boolean` | `BOOLEAN` |
| `char` | `CHAR` | `not` | `NOT` |
| `true` | `TRUE` | `false` | `FALSE` |
| `div` | `DIV` | `mod` | `MOD` |
| `and` | `AND` | `or` | `OR` |

> 注：`BREAK` 在某些 Bison 版本中可能未在 token 表导出，应与 `.y` 文件中的 `%token` 列表保持同步。

### 4.2 运算符与界符

| 词素 | Token | 词素 | Token |
| --- | --- | --- | --- |
| `:=` | `ASSIGN` | `<=` | `LE` |
| `>=` | `GE` | `<>` | `NE` |
| `..` | `RANGE` | `=` | `EQ` |
| `<` | `LT` | `>` | `GT` |
| `+` | `PLUS` | `-` | `MINUS` |
| `*` | `MUL` | `/` | `SLASH` |
| `;` | `SEMICOLON` | `.` | `DOT` |
| `,` | `COMMA` | `(` | `LPAREN` |
| `)` | `RPAREN` | `[` | `LBRACK` |
| `]` | `RBRACK` | `:` | `COLON` |

复合符号必须在单字符版本之前定义，避免被前缀截断（例如 `<=` 不能被先识别为 `<`）。当前规则顺序已遵循该原则。

### 4.3 常量与标识符

| 类别 | Token | 语义值字段 | 语义值含义 |
| --- | --- | --- | --- |
| 整型常量 | `INT_CONST` | `yylval.ival` | `strtol` 解析后的 `int` |
| 实型常量 | `REAL_CONST` | `yylval.fval` | `strtod` 解析后的 `double` |
| 字符常量 | `CHAR_CONST` | `yylval.sval` | 原词素（含外层单引号），堆分配 |
| 字符串常量 | `STRING_CONST` | `yylval.sval` | 原词素（含外层单引号），堆分配 |
| 标识符 | `ID` | `yylval.sval` | 经 `normalize_id` 转小写的堆分配字符串 |

字符串字面量按 Pascal 习惯使用 `''` 表示嵌入单引号（见 `STRING_LIT`）。AST/语义阶段如需获得原始字符内容，应再行去引号。

## 5. 正则定义

`.l` 文件第 109–118 行给出基础正则命名：

```
DIGIT          [0-9]
ID_START       [A-Za-z_]
ID_CHAR        [A-Za-z0-9_]
INT            {DIGIT}+
EXP            [eE][+-]?{DIGIT}+
REAL1          {DIGIT}+\.{DIGIT}+({EXP})?
REAL2          {DIGIT}+{EXP}
CHAR_LIT       '([^\\'\n]|\\[nrt'\\])'
STRING_LIT     '([^'\n]|'')*'
BAD_CHAR_LIT   '[^'\n]*\n
```

要点：

- 实数必须同时支持 `123.45`、`123.45e-6`、`6E10` 三种写法；纯整型不会误判为实型，因为 `REAL1` 要求小数点，`REAL2` 要求指数。
- `CHAR_LIT` 仅允许转义 `\n \r \t \' \\`，与 Pascal-S 教学规范保持一致。
- `BAD_CHAR_LIT` 是一个有意识地匹配「单引号开头但在本行未闭合」的兜底规则，用于产出明确的错误信息而不是 `.` 兜底。
- 字符串 `''` 序列代表一个单引号字符，匹配规则 `'([^'\n]|'')*'` 即体现该约定。

## 6. 状态机

词法器使用两个状态：

- `INITIAL`（默认）：处理常规 Token
- `COMMENT`：处理 `{ ... }` 块注释

状态转换：

```
INITIAL --"{"-->        COMMENT
COMMENT --[^\n}]+-->    COMMENT
COMMENT --\n-->         COMMENT  (g_line++)
COMMENT --"}"-->        INITIAL
COMMENT --<<EOF>>-->    error: "未闭合注释"
```

`//` 行注释一次性匹配 `"//"[^\n]*`，不需要独立状态。

## 7. 源位置维护

Flex 自带 `yylineno` 仅记录行号且与 `yyrestart` 配合存在重置陷阱，因此本模块自行维护：

```c
static int g_line = 1;
static int g_col  = 1;
```

每次匹配后由 `advance_position(yytext)` 推进，遇到 `\n` 重置列号。Token 起始位置在 `mark_token_start()` 中记录到 `yylloc.first_*`，结束位置在 `advance_position` 中写入 `yylloc.last_*`。

整体顺序约定为「先记起点 → 计算语义值 → 再推进位置 → 返回 Token」，封装在 `RETURN_SIMPLE_TOKEN` 宏中。`lexer_reset_position()` 在每次进入 `parse_pascal_stream` 时被调用，保证多次解析互不影响。

## 8. 错误处理策略

### 8.1 错误分类

| 错误 | 触发规则 | 是否消费输入 |
| --- | --- | --- |
| 非法字符 | `.` 兜底 | 消费一个字符 |
| 以数字开头的标识符 | `{DIGIT}+{ID_START}{ID_CHAR}*` | 消费整段词素 |
| 未闭合字符常量 | `BAD_CHAR_LIT` | 消费到行尾 |
| 未闭合注释 | `<COMMENT><<EOF>>` | 终止扫描 |

「以数字开头的标识符」单独建立专用规则，目的是吞掉整段非法词素，避免兜底 `.` 把同一段错误拆成多次报告。

### 8.2 错误计数与早停

所有错误经由 `note_lex_error()` 统一计数：

- 累计到 `kMaxLexErrors`（= 20）触发早停：设置 `g_lex_stop_scanning = 1` 与 `g_lex_scan_terminated_early = 1`，并打印「词法错误过多，停止扫描」。
- 每次匹配前由 `YY_USER_ACTION` 检查 `g_lex_stop_scanning || pascal_s_should_stop_scanning()`，命中即 `return 0` 表示 EOF。这样既支持词法自身的早停，也支持语法分析侧主动要求停止。

### 8.3 错误状态导出

| 函数 | 含义 |
| --- | --- |
| `lexer_had_error()` | 当前扫描周期是否出现过词法错误 |
| `lexer_error_count()` | 累计词法错误数 |
| `lexer_scan_terminated_early()` | 是否因错误过多或未闭合注释提前终止 |

`yyerror()` 在 `lexer_scan_terminated_early()` 为真时不再继续报告语法错误，避免一次词法早停引发后续大量虚假语法噪声。

## 9. 与语法分析的协作

```
+--------------------+        yylex()          +--------------------+
| pascal_s_lexer.l   | ----------------------> | pascal_s_parser.y  |
| (Flex)             |   Token, yylval, yylloc | (Bison)            |
|                    | <---------------------- |                    |
+--------------------+ pascal_s_should_stop_   +--------------------+
                         scanning()
```

约定：

1. 进入 `parse_pascal_stream` 时调用 `lexer_reset_position()` 与 `yyrestart(input)`。
2. 语法器累计错误超过阈值时设置 `g_parse_stop_requested`，词法器在下一次匹配前看到 `pascal_s_should_stop_scanning() == 1` 即结束扫描。
3. 解析结束后，前端通过 `pascal_s_had_lexical_error()` 与 `pascal_s_had_syntax_error()` 综合判断是否进入下一阶段。

## 10. 内存管理

- `dup_text` / `normalize_id` 返回的字符串由 Bison 动作或后续 AST 节点接管所有权；AST 释放时统一 `free`。
- 整型与实型常量的语义值是值类型，不存在所有权问题。
- 词法侧不持有任何 Token 缓冲（Flex 自带 `yytext` 仅在当前动作内有效）。

## 11. 关键不变量

- 任意时刻，`g_line`、`g_col` 指向「下一个待读字符」的位置；这是 `yylloc.last_*` 的语义。
- `yylloc.first_*` 总是在动作开头由 `mark_token_start()` 设定，禁止把它的更新交给 Bison 默认 `YYLLOC_DEFAULT`，否则会与多行 Token（字符串、块注释跨行）产生偏移。
- `kMaxLexErrors` 一旦命中，词法器只返回 `0`，不再返回任何业务 Token，也不再报告新的词法错误。

## 12. 可扩展点

- **新增保留字**：在 `.l` 中追加规则并在 `.y` 的 `%token` 列表中同步登记；保留字规则必须放在 `{ID_START}{ID_CHAR}*` 规则之前，否则会被识别为 `ID`。
- **十六进制 / 八进制常量**：新增正则命名（如 `HEX  0x[0-9A-Fa-f]+`），在 `INT` 规则之前匹配，并选择合适的 `strtol` 基。
- **多行字符串**：当前 `STRING_LIT` 显式禁止换行，如需放开，应拆解为带 `\n` 计数的动作版本，并相应更新 `BAD_CHAR_LIT`。
- **更友好的错误消息**：可以在 `note_lex_error` 中追加结构化错误对象，与 `yyerror` 共享同一错误收集器，统一向调用方报告。

## 13. 与构建系统的关系

`CMakeLists.txt` 中应保证 `pascal_s_lexer.c` 与 `pascal_s_parser.tab.h/.c` 的生成依赖正确：

- `pascal_s_lexer.l` 依赖 `pascal_s_parser.tab.h`（需要 Token 编号）。
- Bison 必须先于 Flex 执行，或在 CMake 中通过 `add_custom_command` 指定显式依赖，避免首次构建因头文件缺失失败。

## 14. 测试建议

最低限度的回归用例集合应覆盖：

- 全部保留字与运算符的单 Token 识别
- 大小写不敏感（`Begin`、`BEGIN`、`begin` 均被识别为 `BEGIN_KW`）
- 整型 / 实型 / 指数三种数值，含边界值
- 字符与字符串字面量，含 `''` 嵌入单引号
- 块注释与行注释（含跨行块注释）
- 错误用例：未闭合注释、未闭合字符常量、以数字开头的标识符、随机非法字符
- 错误风暴用例：构造 ≥ 20 个词法错误的文件，验证早停机制生效且不再产出 Token

可以将上述用例归档至 `testing/lexer/` 并以 `pascc_dummy` 入口跑一遍，比对 `lexer_error_count()` 与 stderr 输出。
